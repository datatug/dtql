# A3 amendment — scoped alternating include/exclude stages

Status: user-directed semantic correction after the A2/S1 review checkpoint. This amendment is not covered by those reviews and is not an implementation authorization. It supersedes the flat "exclusions always win" proposal for new masks. The reviewed legacy fields behavior, policy hierarchy and restrictive composition across owners remain unchanged. Existing frozen review inputs/manifests remain historical evidence; schemas and executable package fixtures are revised below and the delta must be reviewed before a new contract freeze.

## Selected-set semantics

A mask consists of a variable-length list of stages. Each stage holds an include or exclude action and a list of patterns. Patterns within the same stage are ORed. Every following opposite-action stage applies only to the exact set matched by the previous stage, including all ancestor constraints. It cannot select names outside that set. Inclusion may therefore restore part of a preceding exclusion, without becoming a global override.

For the user's example:

```text
include a*, b*
  exclude *c*
    include **d, a*f
```

Let A be names starting with a or b, C names containing c, and D names ending in d or matching a*f. The permitted set is:

```text
(A minus C) union (A intersect C intersect D)
```

Equivalently, start excluded. For a particular name, process the stages from the beginning: if it matches a stage, set its inclusion state to that stage's action and continue; at the first nonmatching stage, stop and keep the last applicable state. This is bounded name matching, not enumeration of a database or schema. A deeper include cannot override a denial in a different mandatory policy or layer.

| Name | Reason | Included? |
|---|---|---|
| apple | Initial include; does not match the exclusion | yes |
| bacon | Initial include, then contains c; no restoring pattern | no |
| abcd | Initial include, excluded by c, restored by ending d | yes |
| acf | Initial include, excluded by c, restored by a*f | yes |
| bdf | Initial include; exclusion never applies | yes |
| zcd | Outside initial selected set, despite matching later patterns | no |

## Portable shape

Use the same stage form for procedure names, collection names and column patterns:

```yaml
stages:
  - include: ["a*", "b*"]
  - exclude: ["*c*"]
  - include: ["**d", "a*f"]
```

Each stage has exactly one action key with a nonempty pattern list. Stage order is semantic and MUST be preserved through editing/serialization. Consecutive entries of the same type form one OR-list and can be canonically merged before evaluating the next action change; they are not successively intersected. The initial stage is include; "all except sys_*" is include:["*"] followed by exclude:["sys_*"]. An omitted mask retains its existing no-extra-restriction meaning; an empty explicit stage list is invalid rather than unrestricted.

There is no fixed semantic number of stages or patterns. Owners still advertise operational input/depth/work budgets and reject excessive requests explicitly; they must never silently truncate the list or drop later exclusions. The reference deployment advertises maxMaskStages=1024 and maxMaskPatterns=4096 per policy document before normalization, maxMaskPatternBytes=128; owners may configure other finite supported limits and clients discover them. The schema has variable-length arrays without a semantic maximum. The existing whole-policy/body and execution/dry-run deadlines still apply. Reject overload at validation or return explicit budget failure; never truncate or treat partial mask evaluation as allow. Stages are a flat list, so predicate AST depth16 does not limit stage count.

## Pattern grammar correction

The user's *c* and a*f require interior and multiple wildcard positions, which the reviewed S1 one-edge-star restriction rejected. New mask syntax therefore supports ordinary anchored glob `*` at any position within a name/field segment. Each * matches zero or more characters. Consecutive stars, including **d, mean the same as one star (*d); they do not introduce recursive path traversal. The user confirmed this interpretation; it is not a recursive path language. Collection/procedure names remain canonical single segments; column dots separate nested segments. Wildcards never cross those structural boundaries.

Extend DALgo's parsed mask machinery for the new profile, preserving its legacy fields parser/matcher. Use bounded glob matching without backtracking regex construction. Do not enumerate all schema fields to compile away the stages. Parent-object projection versus complete evidence, affected-descendant write checks and scalar-reference restrictions from S1 continue to apply against the final staged decision. A restored child does not imply that the whole parent is readable.

## Exact integration and canonical form

collectionMask and fieldMask both use `{stages:[stage,...]}`. Stored-procedure execution entries use `{class:stored_procedure,namespace,mask:{stages:[...]}}`; DTQL/native class-only entries stay unchanged. Reject duplicate execution entries for the same class/namespace rather than allow a second entry to bypass an exception chain. The A2 flat include/exclude form was never implemented or released; it is not accepted as an ambiguous alternative in the new schema. Its examples migrate exactly to include then exclude stages.

Stage object: exactly one key include or exclude with a nonempty string array; unknown keys reject. First raw stage must include. Before evaluation, merge each maximal consecutive run of the same action by unioning its patterns; this establishes the selected set for the next opposite-action stage. Only then apply scoped stages. Canonical serialization collapses consecutive stars within segments, sorts/deduplicates patterns within each merged stage, preserves order of action changes, and never sorts stages. Both JSON and YAML refer to the same normalized AST. Raw formatting/comments remain out of scope.

Scalar name matching uses canonical Unicode characters, exact case and anchored glob semantics. * may occur anywhere and matches zero or more characters in that segment, never a dot/path separator. New masks reject surrounding whitespace, controls, escapes, ? and character classes. nameMask is one canonical procedure/collection segment; fieldPattern is dotted segments with existing parent-prefix matching. A pattern matching a parent continues to select its descendants, but child stage selection and restoration are always evaluated on the concrete field path under all prior selections. Legacy fields parsing/grammar remains unchanged.

C2 field_mask restriction still uses representation mask, but mask now contains stages. Do not emit a flattened include-minus-exclude approximation. Ordinary blockers remain ACL_COLLECTION_DENIED/ACL_COLUMN_DENIED/ACL_CALLABLE_DENIED with owner/policy provenance; the evaluator may retain stage indexes internally, but no required new English text or public diagnostic fields are needed. If a disclosed mask is too large or private, return the existing opaque reference; never disclose only its positive stages.

Complete parent-object evidence remains conservative: if any descendant exclusion can apply under the staged mask, reject whole-parent evidence unless complete-subtree authorization can be proven. MVP need not implement a glob-language inclusion solver; it may conservatively reject such parent evidence even if a later stage would restore every excluded descendant. Concrete authorized leaf evidence remains possible. A parent's being projectable does not make it complete evidence. Scalar-only query references and final affected-descendant write checks remain mandatory. No stage can restore a value denied by another mandatory policy or owner.

The standard deny-column UI continues to offer a fixed explicit fields list. Advanced staged masks show the initial selection and successive scoped exceptions, preserve action-change order and distinguish future-field wildcard inclusion. Stage reordering changes policy meaning; saves validate and persist at the owner with normal revision CAS. Unknown/stale clients must not edit a staged mask through flat controls.

# Collection and column masks — integration requirements

A3 [scoped stages](19-scoped-mask-stages.md) supersedes the earlier flat include/exclude syntax and unconditional exclusion precedence. This document retains the security and integration obligations reviewed in A2/S1. The exact original S1 is preserved in reviews/round-2/input-A2-S1.txt.

## Reuse verified against existing DALgo

At audited DALgo commit `6b0be09b95bd3afc90309763671791e17264dffe`, `access/fields.go` already parses per-segment literal, `*`, prefix* and *suffix masks, supports dotted paths/parent descendants, and intersects `fieldSets`. It has no exclusion set. Extend that same parsed representation with exclusions and reuse its segment matcher; preserve legacy `fields` behavior. Do not expand masks into a schema snapshot or add a competing evaluator.

New masks extend the same parsed machinery with scoped stages and arbitrary-position segment stars under 19. Legacy fields keep their old grammar. Lists are variable length with advertised operational budgets; no later stage may be silently dropped.

## Collection mask

Add optional `collectionMask:{stages:[stage,...]}` to AccessPolicy. It is a **mandatory conjunctive admission gate**, like execution, not a wildcard path with invented specificity. It applies to every data operation assessed by that policy, irrespective of which bound rule allows it. Omission adds no collection gate. When present, evaluate the normalized owner collection through the scoped stage chain in 19. Later inclusion can restore only its preceding excluded subset. No match is `ACL_COLLECTION_DENIED` with table scope; another independent policy or owner cannot override it.

MVP targets single root collections. Match canonical collection base name resolved from the parsed query/key, not caller display aliases; preserve the owner's database identity. Existing `path`/rule hierarchy still decides ordinary operations, row/field restrictions and bindings. The collection gate cannot grant an ordinary action that the policy denies. Nested/collection-group/native requests whose touched collections cannot be fully resolved are unsupported under this profile, never treated as matching `*`.

Example complete narrowing policy (applicable to all authenticated subjects already admitted by other mandatory policies):

```yaml
apiVersion: dtql.org/access/v1
kind: AccessPolicy
metadata:
  name: public-customer-surface
  visibility: public
target:
  database: crm
composition: dalgo-hierarchical-v1
default: deny
collectionMask:
  stages:
    - include: ["*"]
    - exclude: ["sys_*"]
execution:
  allow:
    - class: dtql
scopes:
  - path: /
    rules:
      - id: surface
        effect: allow
        operations: [get, exists, query, insert, set, update, delete]
        fieldMask:
          stages:
            - include: ["*"]
            - exclude: ["secret_*", "address.internal_*"]
```

This narrows access to non-sys_ root collections and permitted columns. It does not replace the required tenant/country/workflow policies or grant the actions they deny. For only User_* collections, use a single include:["User_*"] stage. Schema discovery applies this gate before collection enumeration/pagination. Public policy text intentionally discloses its mask literals subject to ordinary policy read authority.

## Column mask

Add optional `fieldMask:{stages:[stage,...]}` to an **allow** rule, mutually exclusive with legacy-compatible `fields`. Deny rules forbid both. `fields:[...]` retains exact existing semantics and is not silently reserialized as fieldMask. A fieldMask parses to a staged restriction within the existing fieldSet machinery. Use the selected-set algorithm in 19. A matching parent pattern covers descendants; subsequent scoped stages may exclude or restore a subset. Independent field sets still intersect. A literal dotted field pattern always means nested segments, never a literal dot in a physical key. Reject ambiguous physical keys at protected normalization/evidence boundaries as specified in C1.

Column patterns reuse current DALgo dotted segment grammar and parent/subtree semantics: `address.*` selects descendants and current parent-prefix behavior; `address.internal_*` excludes matching nested fields and their descendants. The implementation must not return an object wholesale just because its parent is included: recursively redact excluded descendants. Setting/replacing a parent validates every affected descendant, including removed fields; a finally excluded child blocks whole-object replacement even if its value is unchanged when the operation touches it. Arrays and complex provider paths are unsupported unless existing conformance proves complete affected-path handling.

Apply masks to explicit projections, filter/sort references, evidence coverage, schema visibility and actual write field paths. Query allow alternatives retain DALgo's conservative **intersection**, now intersecting each fully evaluated staged set; point/write decisions retain the first deciding rule. No union of different policies' includes can defeat another's exclusion. For wildcard reads recurse/project safely before emitting data. A new column matching include:["*"] is allowed unless excluded; explicit legacy field lists continue to deny unlisted new fields. The UI must show this difference instead of promising that every future column defaults denied.

C2 adds restriction kind `field_mask`, representation `mask`, with required mask:{stages} and no expression/fields/omissionReason. A private or oversized mask becomes a coalesced reference, with kind field_mask or opaque, following the same privacy rules. Existing field_allowlist/fields variant remains. Collection gates are static operation decisions/blockers; no residual mask is needed for the single resolved collection. Return `ACL_COLUMN_DENIED` for excluded columns, not a second column taxonomy. Column names in diagnostics still require safe request/evidence disclosure.

# DTQL ACL policy format and semantics — proposed v1

Contract C1. Proposed `apiVersion: dtql.org/access/v1`; this identifier is a version discriminator, not a claim that a public schema URL is already deployed. DTQL owns this portable contract; DALgo supplies its first conforming implementation. `dalgo.io/access/v1` remains accepted by existing legacy decoders. Do not silently reinterpret or rewrite legacy documents.

## Reuse and representation

Canonical editable text is UTF-8 YAML 1.2 in its JSON-compatible subset; JSON represents the same abstract document. This adopts DALgo's existing document and condition shape rather than creating a policy DSL. The first portable profile supports existing hierarchical allow/deny, row `where/check`, field **allow-lists**, and principal bindings. The [reviewed mask extension](18-mask-supplement.md) adds collection and column include/exclude sets within the same evaluator. A UI “deny column” action produces an explicit allowed-field restriction in a separate policy against the current schema; it never invents a `deny fields` rule that DALgo cannot execute. New fields stay denied by that explicit list. Predicate-bearing deny rules are unsupported in this profile; represent positive admissible rows rather than introducing negation semantics.

```yaml
apiVersion: dtql.org/access/v1
kind: AccessPolicy
metadata:
  name: tenant-access
  visibility: private
target:
  database: crm
composition: dalgo-hierarchical-v1
default: deny
ruleSets:
  editor:
    - path: /customers
      rules:
        - id: read-tenant
          effect: allow
          operations: [get, exists, query]
          where:
            op: "=="
            left: {field: tenant}
            right: {param: tenant}
        - id: update-tenant
          effect: allow
          operations: [update]
          where:
            op: "=="
            left: {field: tenant}
            right: {param: tenant}
bindings:
  users:
    user-alice: [editor]
  roles:
    crm-editor: [editor]
  groups:
    crm-team: [editor]
```

The example names an opaque user in the configured identity realm. Real deployment uses its established ID, not an OAuth subject or display name. `tenant` is a host-resolved trusted authorization attribute, never a query-supplied parameter. This policy denies operations not explicitly granted; a fixture requiring other operations supplies corresponding rules.

## Document grammar

All maps reject unknown keys. Keys are case-sensitive. Nonempty strings are bounded to 256 UTF-8 bytes unless otherwise specified. IDs use `[A-Za-z0-9][A-Za-z0-9._-]{0,127}` for policy/rule/rule-set IDs. Principal binding keys are opaque strings bounded to 256 bytes, interpreted within the owner's realm; they need not obey the policy ID grammar.

| Field | Required type and meaning |
|---|---|
| `apiVersion` | Exact string `dtql.org/access/v1`. |
| `kind` | Exact `AccessPolicy`; audit-selection policies remain separate and never authorize data. |
| `metadata` | Object with required `name`, stable policy ID; optional `description` ≤2048 bytes, non-normative author text; optional `visibility: private|public`, default public. |
| `target` | Object with required `database`: exact local owner database ID. No regex or wildcard in MVP. Mount aliases resolve server-side to the owner's database ID before evaluation. |
| `composition` | Required exact `dalgo-hierarchical-v1`; unknown value rejects. Across documents composition is always intersection. |
| `default` | Required exact `deny`. |
| `scopes` | Nonempty scope array for a policy applying to every principal; mutually exclusive with `ruleSets/bindings`. |
| `ruleSets` | Nonempty map of rule-set ID to nonempty scope array, required with `bindings`. |
| `bindings` | Object with `users`, `roles`, `groups` maps to nonempty arrays of existing rule-set IDs, and optional `everyone` array. At least one binding required. Matched sets deduplicated. |

A scope has exactly one selector `path` (string), `collectionGroup` (string), or `opaqueQuery: true`, plus nonempty `rules` and/or child `scopes`. MVP wire interchange can preserve the latter two legacy selectors, but loading either into an enabled protected owner rejects the complete candidate set as ACL_CONFIGURATION_INVALID; never ignore an unsupported scope. Representable unconditional truncate rules may load, but invoking truncate is always unsupported in the protected profile, so such rules cannot reopen an execution path. A disabled legacy source does not thereby gain the new profile's conformance claim.

A rule has required `id`, `effect` (`allow` or `deny`), `operations` (nonempty array); optional `where`, `check`, `fields`. IDs are unique within a plain policy and within each rule set; the qualified rule ID is `ruleSet/rule` for bindings. `fields` is a nonempty array of patterns; absence means all fields, and explicit `[]` rejects to avoid omission/empty serialization ambiguity. `where/check/fields` are allowed only on `allow`. `check` without `where` constrains new data but not reads. Neither `where` nor `check` accepts explicit null.

Leaf operations: `get`, `exists`, `query`, `insert`, `set`, `update`, `delete`, `truncate`. Authoring conveniences `read`, `write`, `readwrite` expand to the existing leaf sets. Conditional/field-restricted groups must canonicalize to explicit supported leaves and exclude truncate; explicit restricted truncate is invalid. New serializers emit explicit leaves in that order. Unknown operations reject. `truncate` is representable but not executable in MVP. CRUD on policy resources uses a separate administration action namespace, never these data grants.

## Paths, fields, expressions

Path selectors reuse DALgo alternating collection/record segments: `/customers`, `/customers/123`, `/spaces/{spaceID}/customers`. Scopes apply to descendants. Nested fragments append structurally; canonical output uses the same nested tree, not a semantic flattening. `*` and `{capture}` only occupy record-ID positions; `/**` is optional terminal inherited-subtree notation, not arbitrary glob syntax. Root `/` matches all logical resources. Only string record IDs are portable in this profile. IDs containing reserved separators use percent encoding decoded exactly once into structural segments; adapters must use the common normalizer, never filesystem string concatenation. Reject malformed encodings, empty segments, dot traversal, invalid wildcard placement and collisions after normalization. Preserve case; no Unicode/case-fold aliasing.

Field names are dotted paths using DALgo's existing `fields` patterns (whole-segment `*`, permitted prefix/suffix wildcard forms). A concrete request uses field segment arrays on the wire, making nested `address.city` unambiguous. Literal dots in a segment, ambiguous pattern escapes and whole-object replacements under descendant-only grants are rejected by the portable profile until lossless common escaping is specified. MVP UI offers schema field checkboxes and exact names; it preserves read-only supported patterns rather than expanding arbitrary wildcard expressions into a lossy form.

Conditions use exactly one of `{op,left,right}`, `{and:[conditions...]}`, `{or:[conditions...]}`. Groups must be nonempty. Left is `{field: name}`. RHS is `{value: scalar}`, `{values: [scalars...]}` for `In`, or `{param: name}`. Scalar: string, boolean, null, or finite number in the cross-runtime exact range; integers are limited to ±(2^53−1), with larger IDs encoded as strings. No arbitrary objects, YAML tags, timestamps or execution expressions. Comparisons are `==`, `In`, `>`, `>=`, `<`, `<=`. Missing fields do not match; explicit null only equals null, is not ordered. Numeric comparison uses numeric values without string coercion; incompatible types return a safe evaluation error. String ordering is UTF-8 lexical, not locale/collation-dependent. Adapters unable to match these semantics must reject the operation or use proven equivalent enforcement before paging.

Authorization params are `currentUser`, `principal.roles`, `principal.groups`, `now`, declared host attributes such as `tenant`, and valid `path.<capture>`. Resolve each once from a trusted snapshot; a missing variable fails closed. `now` is a finite integer Unix timestamp in milliseconds in the exact numeric range, read once from the host clock per layer; it is not a client timestamp. Policies comparing timestamps must use that numeric representation; string/date coercion is forbidden. principal.roles/principal.groups and other list-valued params are valid only as In RHS; other operators return ACL_EVALUATION_FAILED. Scalar In RHS is a type error. No filesystem/env/network expressions. The MVP cross-layer fixture uses no time-dependent expressions. Query parameters have a distinct untrusted namespace and cannot override these variables.

## Within-policy evaluation algorithm

1. Resolve the verified subject in the owner realm. `users` matches only kind `user`; service/application/agent subjects match only explicitly assigned roles/groups or `everyone`. `currentUser` is the stable ID for human users only; use with another kind is an unresolved-variable error. Select `everyone` and matching user/role/group rule sets; union and deduplicate them. No match leaves a default-deny policy. Prefix rule IDs by rule-set ID and sort deterministically; declaration/map order is not authority.
2. Select rules matching operation and structural resource. Sort descending path depth, descending literal specificity, restrictive effect first, then ascending qualified rule ID.
3. Unconditional rules decide the remaining space. Conditional allow rules ahead of that terminal authorize only rows meeting their predicates. A deeper allow may reopen a less-specific deny; an equally specific deny precedes allow.
4. For read row eligibility, conditional alternatives are ORed, bounded by the first unconditional rule. An unconditional allow makes row eligibility unrestricted, though field restrictions remain. Query field bounds conservatively intersect all possible deciding allow alternatives in the current DALgo profile.
5. For an existing-row write choose the first alternative whose pre-image `where` is true, otherwise terminal allow; do not fall through to a later allow after that chosen rule's field or post-image check fails. For a new row choose the first alternative whose effective check succeeds, then check fields. `check` defaults to `where`. No admitting alternative means deny.
6. Intersect independently applied policies. Conjoin their row obligations and intersect their field sets. A denial in one policy is never reopened by another.

Policy IDs and rule IDs affect stable attribution; rule ID also currently breaks equivalent-priority ties. The editor must warn that renaming a rule can change precedence. MVP does not add policy renaming or arbitrary rule-order controls. Migration tests must prove equal decisions for legacy supported constructs, including this tie behavior.

## Provenance and round-trip editing

Policy visibility is owner-enforced classification. `private` hides policy identity, text, rules, predicates and policy-specific references from every caller except an explicitly authorized **policy admin at that owner**. Discovery/read/Explain/diagnostics privileges alone cannot reveal a private policy. `public` merely permits ordinary owner authorization checks to disclose it; it is not public unauthenticated access. Create/import defaults public. PUT omission preserves the stored visibility; canonical serialization always emits the effective visibility explicitly. A non-admin cannot change classification by omitting it. Changing this classification requires owner policy-admin authority, independently of ordinary edit permission. The owner persists and attests the effective classification and rejects a non-admin replacement that changes it. Legacy imports default public. Private restrictions may still return opaque request-scoped restriction IDs/generic denial without revealing hidden policy count or identity. These IDs cannot be dereferenced by non-admins. Classification applies to cached responses and audit access as well as policy download.

Source, owner, layer, resource mount, Git revision and editability are returned in an **owner-attested envelope**, not trusted from user-editable text. `metadata.name` identifies the policy locally; global identity is `(ownerId, databaseId, policyId)`. A fetched descriptor includes the revision/ETag and source reference. Export may bundle that envelope beside the document, but import must discard claimed authority and obtain provenance from the new owner.

MVP promises semantic round-trip and canonical idempotence: parse → document AST → edit → validate → serialize → parse preserves all supported fields/meaning; a second canonical serialization is byte-identical. It does not preserve comments, original whitespace, quoting, anchors or source ordering. Reject anchors/aliases, duplicate keys, merge keys, custom tags, multiple YAML documents and duplicate JSON object keys. This is stronger than assuming generic decoder unknown-field rejection suffices. Normalize map keys lexically, operation arrays to leaf order, subject/rule-set references as sorted sets; keep semantic scope/rule structures and qualified IDs intact. The UI explains that saving canonicalizes formatting. Raw text editing is optional, but parse/serialize APIs support it.

Unknown-version, custom or nonportable policy documents remain represented by read-only descriptors. Never edit through a reduced AST and drop unsupported fields. A supported document with complex scope/pattern structure outside the form editor's fidelity can likewise be read-only or edited through the optional raw editor. Legacy conversion is an explicit owner-admin action with before/after differential fixtures; do not strip `target`/`composition` and call that a complete migration.

## Execution routes and scoped masks

C7 optional execution is a conjunctive gate in the same AccessPolicy/evaluator. Omission adds no route restriction; a present allow array defaults to deny for unlisted classes. Entries are class:dtql|native_sql|native_graphql|stored_procedure; procedure entries also require exact canonical namespace and a staged mask as defined in [19](19-scoped-mask-stages.md). Reject duplicate class/namespace entries. Ordinary action/resource policy checks still apply, and different mandatory policies intersect.

```yaml
execution:
  allow:
    - class: dtql
    - class: stored_procedure
      namespace: public
      mask:
        stages:
          - include: ["User_*"]
          - exclude: ["User_Delete*"]
          - include: ["User_DeleteDraft"]
```

This admits only the scoped callable subset at this gate. Native SQL/GraphQL are unlisted and denied. For every procedure except sys_*, use include:["*"] then exclude:["sys_*"]. A deeper include can restore part of that exclusion, never a lower-owner denial. collectionMask and allow-rule fieldMask use the same stage form, with fieldPattern applying to nested field paths.

executionClass is required in normalized operations; server derives it from the actual route/parsed operation and rejects a conflicting caller label. Calls hidden in SQL/functions/GraphQL cannot bypass procedure restrictions through a native label. The protected MVP permits real DTQL route gating and pure procedure-mask assessment only. All native/procedure effects execution remains unsupported even after a matching mask; no native parser/effects analyzer is added here. Existing DTQL action/table/row/column checks remain mandatory.

# A2 contract completion

Normative completion of C1–C6 following approved H1–H7. JSON shapes are in [contracts](contracts/README.md). These are specification artifacts, not executable ACL implementation. When interpreting A1 sketches, use the exact A2 definitions here; the frozen A1 review bundle remains historical evidence.

## C4 evidence and transaction boundary

Use `access/contract` for protocol DTOs/converters and keep `dal` independent of them. `access` owns internal assessment/evidence types; `access/contract` imports access, never the reverse. Existing `dtql` remains the query parser. Hosts implement provider/identity/storage interfaces; no new evaluator per host.

The following signatures define the implementation seam; named values below are closed internal records, not browser DTOs:

```go
// Proposed API, not added to a Go package in this phase.
type InspectionSession interface {
    Assess(ctx context.Context) (Assessment, error)
}
type ExecutionSession interface {
    InspectionSession
    Execute(ctx context.Context) (ExecutionResult, error)
}
type EnforcementCoordinator interface {
    WithinInspection(ctx context.Context, admission InspectionAdmission,
        inspect func(InspectionSession) error) error
    WithinExecution(ctx context.Context, admission ExecutionAdmission,
        execute func(ExecutionSession) error) error
}
```

`AssessmentPlan` contains normalized operations, immutable owner PolicySnapshots, verified principal snapshot and required evidence paths derived by the shared evaluator. It is constructed internally, never deserialized from HTTP. Both session implementations are unexported concrete, lifetime-checked capabilities supplied only to registered trusted wrappers through the coordinator. A callback cannot retain/use it after return. It exposes decisions/execute, **not** raw Get or a raw database handle. The coordinator privately provides complete pre-images and final candidate images to registered pure owner policy evaluators. Hosts register mandatory participants at mount construction, not per request. The callback may not remove participants. Trusted Go code is a process trust boundary, not a sandbox against malicious callbacks.

The InGitDB adapter owns the coordinator and short storage transaction. Embedded OVDB registers its owner assessment through this seam; nested `SecureDB` must join the same operation token, not open an unrelated transaction or require public Get permission. The coordinator receives a privately constructed immutable admission containing verified principal, predeclared normalized operations and pinned participant registry. It constructs/binds the AssessmentPlan once; callbacks cannot substitute operations or a plan. The two entry methods bind inspection vs execution intent in their types. They acquire locks within the deadline, pin owner policy snapshots, capture one image/revision per unique target and construct candidate images. `Assess` evaluates without mutation; `Execute` performs current required assessments, revision checks and final-candidate checks before staging any mutation. It can run at most once, only through ExecutionSession; InspectionSession has no Execute method and its concrete type must not implement ExecutionSession. Closing commits only after one successful Execute and a successful callback, otherwise aborts. Inspection never starts a write executor. Existing legacy Policy interfaces stay unchanged. The lifecycle table below is normative.

Private evidence record: `{canonicalTarget, snapshotToken, exists, preImage, candidateImage?, dataRevision?, complete:true}`. Absent record has exists=false and no image/revision; a present image includes every field, including explicit null. Schema transformations producing the final candidate must complete without external effects before evaluation. Missing capability, non-pure callback or unavailable final image is unsupported, not an empty image. No raw image crosses an HTTP boundary through this interface. Owner policy-admin authority alone does not grant evidence access.

### Ingress/lifecycle compatibility

| Ingress | Required lifecycle |
|---|---|
| plan | Pure metadata planner; never enters evidence coordinator, acquires data locks or reads images. |
| inspect/sample row assessment | Privately constructed InspectionAdmission; read-only inspection session, one bounded snapshot per assessment. Sampling first selects authorized candidates and uses the same assessment path. |
| concrete execution/single write | ExecutionAdmission with complete normalized operation; all mandatory registered wrappers join the same owner operation token and storage transaction, never recursively reacquire locks. |
| declared batch | Complete unique-target operation list known before admission; one ExecutionSession, preflight all, Execute once, all-or-none. |
| public dynamic RunReadwriteTransaction/RWTxWorker on ACL-enabled DTQL profile | Reject with ACL_ENFORCEMENT_UNSUPPORTED **before invoking the worker**, including workers with two writes, intervening reads or conditional operations. Do not execute a worker to discover its operation list. |
| legacy ACL-disabled or existing legacy DALgo profile | Preserve existing callback semantics. The restriction applies only to the new negotiated protected profile. |

The adapter's unexported coordinator can use the existing raw transaction implementation internally; it is never returned through the secured public handle. Protected single-operation helpers and HTTP declared batches use the coordinator directly instead of routing through the rejected public dynamic callback. Public read/session forwarding remains secured; unsupported alternate handles fail closed. Policy snapshots are fixed for each owner admission; nesting joins the already bound snapshot/plan. This is a documented narrow compatibility limit, not a design for general logical transactions.

### Remote DataTug evidence

Add an authorized point-inspection transport, `POST /v1/databases/{db}/access/evidence`, with body `{apiVersion,resource,requiredFields}`. Evidence resource forbids columns; requiredFields is its sole exact field-coverage list. Its response resource likewise forbids columns. It is an ordinary **data-read-authorized** operation, not an administrative escape hatch. Each owner authorizes Get and the requested concrete fields for the authenticated actor+subject. It rejects sampling, simulation and arbitrary owner predicates. Successful body: `{apiVersion,resource,exists:true,dataRevision,fields:[{path,state:"present",value}|{path,state:"absent"}]}`. For every requested field exactly one entry is required; duplicate/unrequested fields reject. An absent entry is an authoritative assertion of nonexistence in the same complete image, permitted only if the caller may read that field. A withheld field is never encoded as absent: the entire evidence request fails with safe authorization/unsupported result. The ordinary caller's missing and denied projection is identical (below). No response with exists=false is available in this MVP remote evidence shape.

`dataRevision` is opaque, owner-issued, covering the entire record including hidden fields; all field evidence comes from that revision. DataTug requests the union of all dependencies needed to decide its possible winning rules, the mutation paths and any replacement/removal checks. Set requires complete readable pre-image coverage and is unsupported remotely if that cannot be proven, including an upsert requiring proof of absence. No exists=false evidence extension is implied. Candidate-only insert checks remain possible without a remote pre-image; lower insert existence/atomicity is still enforced by storage. No wildcard claim of completeness. The shared evaluator treats unspecified evidence as unknown, never absent or null. DataTug sends the same revision as ifDataRevision with the normalized mutation. Lower owner checks it under the transaction before mutation. Hidden-field-only concurrent changes invalidate it. No client-supplied projection hash or cached Explain result is authority.

This extra endpoint is needed to distinguish redaction from absence; an ordinary projected Get response is insufficient. The driver may reuse a Get only if it exposes exactly this verified coverage/revision contract. Otherwise it must call evidence or fail closed. Evidence is held for one short request and never persisted in policy/UI caches.

### Read constraint trust

Keep caller field references separate from registered owner predicates in process. Owner predicates may use private fields only inside their owner evaluator. Across HTTP an upper-injected predicate is still an ordinary query constraint: lower field authorization applies. Do not accept a provenance label, signature or hiddenField=true as permission to query hidden fields. DataTug requests readable predicate dependencies internally, verifies returned rows against its pinned predicates before publishing the bounded response, then strips internal fields from the browser projection. All lower filters must already have applied before paging; verification failure aborts the response, never filters after paging. An adapter unable to execute these predicates faithfully before paging is unsupported. Sorting/limits and scalar semantics receive driver conformance tests, not an assumption that SQL or attestation makes them equivalent.

## C2 result scope, sampling and disclosure

`AuthorizationResult` requires `mode:plan|inspect|sample|execution` and `scope:request|sample`. Scope is sample iff mode is sample. Each operation result requires `id`, `requestOperationId`, action, concrete resource, result, restrictionIds and allOf. Outside sample id=requestOperationId. Sample accepts exactly one table operation template (get/exists/update/delete) and a query on that table; update requires candidate changes, delete requires empty mutation. The server assigns per-row IDs s1, s2, … in selection order, skipping any ID equal to the request template ID. It retains the mapping when composing lower results: remap all lower operation references into these IDs, never concatenate unrelated hop-local IDs. Row blockers/decisions reference the row ID; requestOperationId maps back to the template. Selection-level blockers, layer decisions, restrictions and unevaluated coverage instead reference the template ID, without creating an operationResult or incrementing evaluatedCount. The template domain represents pre-selection route/table/column denial and unavailable selection; it never implies a row exists. sample metadata includes templateOperationId and selectionResource (table path, no rowId); that diagnostic domain denotes the selection query action, while per-row operationResults denote the requested template action. This makes references intelligible without inventing a row. No per-row decision is returned for a key the requester cannot see. Incomplete selection-level work uses the template ID in `coverage.unevaluated`; IDs there may reference a request template or result operation and the consumer validates that union.

Sample reducer: any definitive selection-level or sampled denial → deny; otherwise required missing evaluation/selection budget → indeterminate; otherwise conditional. A fully evaluated all-allow sample remains **conditional, allowed=false**, because it cannot authorize the general request. Per-row results may be allow. An empty completed sample is conditional with zero operations; sample metadata has evaluatedCount=0 and exhaustive=false. `coverage.evaluation:complete` refers to finishing the bounded sample, never exhausting the table. `sample.order` is an array of concrete field paths/directions ending in the canonical key; no free-text order string. RequestedLimit/evaluatedCount are counts of authorized candidates only. Sampling never broadens visibility using inspect-protected. A partial sample may return already safely evaluated rows with partial coverage; it never executes a write.

Non-sample reduction: definitive denial dominates; then required failed/unevaluated participant gives indeterminate; then residual obligations conditional; otherwise allow. Errors are not converted to policy denials. `allowed=true` iff result=allow, coverage evaluation complete, no truncation, and scope=request. Hypothetical allow is an assessment only, never execution authority. Modes plan/inspect/execution do not have sample metadata. Every non-sample request ID occurs exactly once; synthetic IDs must not collide with template IDs when validating references. In plan, deferred row/post-image checks are explicit restrictions, not missing evidence: do not emit row_evidence_required. That coverage reason is reserved for modes that actually expected evidence.

Each operation's `restrictionIds` and `allOf` have the same unique set; both reference all applicable mandatory restrictions. Keeping explicit allOf avoids interpreting them as alternatives. Disclosed expressions retain the policy's own OR semantics inside that conjunct. Restriction variants:

- expression: kind row_filter or post_image_check, expression required, no fields/omissionReason;
- fields: kind field_allowlist, fields required, no expression/omissionReason;
- mask: kind field_mask, mask ordered stages required; no expression/fields/omissionReason (18);
- reference: kind row_filter/post_image_check/field_allowlist/field_mask/opaque, omissionReason required (private/too_large/unsupported/not_authorized), no expression/fields.

All variants require id, operationId, representation, kind, enforced; layerId/policyRef are optional under disclosure. `enforced=false` in every dry run, even after successful evaluation. In a successful execution it is true only when that obligation was applied at the actual query/write boundary. A denied execution has no obligation marked enforced merely because its evaluator ran. Internal enforcement completeness is separate from external disclosure: one opaque coalesced owner restriction may stand for several private restrictions. Never emit private cardinality, policy revisions, stable hidden IDs or separate per-policy placeholders to non-admins. Non-admin reference omissions use not_authorized, never private; private is only available to an owner policy admin already authorized to know that classification. All public identifiers/references are checked for referential integrity after redaction.

`access:diagnostics` permits public policy references but no extra data visibility. Concrete protected-row existence/predicate facts require either ordinary authorized read visibility or an explicit owner `access:inspect-protected` grant for that key. The latter authorizes facts only; no image values, broad enumeration or private policy names. Policy admins need that separate grant to inspect unreadable data. Each owner independently projects its facts; upstream may only remove more detail.

Ordinary point Get/HEAD/evidence/update/delete probes of a nonexistent or non-disclosable denied key return the same HTTP 404 `resource_unavailable` outer error and generic ACCESS_DENIED authorization projection, without row-specific facts. This public projection may replace an internal deny/not-found distinction; it never reports allow. Use the same projection for dry-run key probes in a 200 result, coalescing to generic deny. Invalid syntax/auth failures and static table/column denial independent of existence retain their usual status. Enhanced authorized inspection can report row-specific facts but still no raw values. Data revision conflicts are returned only after access and existence disclosure are authorized; otherwise use the safe projection, not a revision oracle.

## C5 bounded execution and batches

Reference profile limits: query default/max 1,000 returned rows, max offset 10,000, max 8 MiB buffered result, execution deadline 10 seconds from ingress; dry run deadline 2 seconds, sample N≤100. Earlier limits on requests, expressions and facts remain. Each hop propagates the remaining deadline, never resets it; lock acquisition consumes it. Adapter inability to enforce bounds fails before execution. Buffer overflow or query deadline produces no partial query success. Dry runs may return explicitly partial diagnostics. No background mutation continues after cancellation before commit. If a response is lost or cancellation arrives after the commit point, the outcome can be uncertain; do not promise safe automatic retry or introduce idempotency/transaction protocols here.

A real batch is ≤100 operations with distinct IDs and **unique normalized record targets** across all operations, including differing path aliases resolving to the same owner key. Reject duplicates before evidence/mutation with 400 `duplicate_record_target`. Require one capable storage transaction and one owner database; cross-database/source batches are unsupported. Each item carries its own ifDataRevision when required. Capture/preflight all, check all revisions and final candidates, then apply all or none. A denied item collects other safely evaluable blockers and causes zero mutations. A revision conflict maps to that item in the non-ACL error detail and causes zero mutations. Dry-run multiple operations are independent snapshot assessments, never sequential hypothetical changes; they may mention a key more than once and cannot be submitted as a change-set authorization token.

## C5 policy publication and process-crash recovery

Filesystem owners (OVDB/DataTug): immutable generation directory with manifest, policy files, exact digest and enabled/realm configuration; write temporary generation, validate complete candidate, fsync files and directory, rename to immutable digest name, fsync parent. If that digest already exists, verify complete matching bytes and reuse it; do not overwrite an invalid existing generation or fail a valid no-op edit merely because the directory exists. Under cooperating owner publication lock/CAS, write and fsync temporary active manifest referencing that digest, atomically rename over active manifest, fsync directory; this rename is publication point. Publish in-memory snapshot before reopening admissions/responding success. Startup reads only the active manifest, validates referenced digest/files, and loads that complete generation. Incomplete/unreferenced generations are ignored, never inferred active. Crash before/after activation yields old/new complete generation. Filesystem adapters without these primitives are unsupported for editable stores. Missing active manifest on an enabled configured owner fails closed, never legacy mode.

InGitDB additionally uses Git as the authoritative committed policy pointer. Require a clean policy/config tracked subtree at mount/edit; unrelated dirty data is not staged by policy CRUD. Under the existing cooperating repository writer lock, materialize and fsync the complete immutable generation, construct a Git tree from current HEAD changing only policy subtree/config, and create a commit using expected-parent compare-and-swap. Atomic HEAD update is the **policy commit point**. Do not use a partial working-tree manifest as active truth. After commit, refresh working active manifest to the committed pointer and publish the compiled snapshot before admission resumes/success response. Startup holds the cooperating lock while reading committed HEAD and verifying/materializing only its policy subtree and activating it. Read-only mounts may serve only if the committed generation can be validated without materialization using existing adapter capability; otherwise refuse the mount as unsupported, with no new committed-blob loader required; a crash before HEAD update keeps the old committed generation, after update recovers the new one even if working pointer/memory lagged. Never rewind HEAD to undo an already committed policy update. Returned commit failures before HEAD update preserve old state; failures afterwards are uncertain success and recover on restart. Git commit carries provenance; policy revision is the generation content digest, independent of unrelated data commits. Ref updates and generation writes require the existing lock; noncooperating filesystem/Git administrators remain outside the threat boundary.

Process-crash tests kill between each numbered physical phase (generation write, fsync, rename, commit creation, HEAD CAS, working pointer, in-memory activation). Restart must serve old or new complete committed policy, never a mix or disabled ACL. Do not automatically repair arbitrary corrupted committed policy: fail closed and require owner repair. No distributed transaction, background recovery service or general data change-set protocol is introduced.

### Revision domains and retention boundary

Internal generationRevision covers the complete owner set/config and is never a public document ETag. Each policyRef.revision and policy CRUD ETag covers only that document's effective canonical bytes/identity; unchanged public policy retains its revision after a private-only edit. Under the owner lock, PUT compares the target document ETag, merges the replacement into the **current** set, validates that set and publishes a new internal generation. Concurrent private edits are preserved; a stale whole-set token is neither required from nor disclosed to the public editor. Non-admin responses always omit whole-set layer policyRevision, regardless of whether a private policy exists; internal attribution/redaction uses private generation tokens without leaking them. Admins may receive whole-set revision. Public caches use their visible documents' ETags; no hidden-state change feed is implied.

Unreferenced generations remain inactive and may consume storage. Retention and cleanup are operator/follow-up work, not a new MVP GC subsystem or a condition for authorization correctness. Do not prune Git history as part of policy CRUD. Existing validated digest reuse prevents duplicate content writes; recovery never activates an unreferenced generation.

## C6 schema and DDL

Advertise `schema:read` as a separate owner capability. Field-filtered schema discovery intersects caller+subject visible field bounds at every owner and exposes only accessible collection/field names and safe scalar types. It does not expose hidden constraints, defaults, row counts or sensitive validation expressions. If a source cannot filter safely, return unsupported/generic metadata. Public policy text may intentionally reveal its public field selectors; schema filtering does not make public policy literals secret. Full schema metadata administration remains out of band. DDL is explicitly unsupported on ACL-enabled MVP data endpoints even for data/policy admins; setup provisions fixture schema before enabling ACL. This closes a bypass boundary without a new DDL policy language.

# A2 machine-readable specification artifacts

[acl.schema.json](acl.schema.json) is JSON Schema draft 2020-12. Select `$defs.policy`, request, result, policyWrite, policyEnvelope, policyPage, layersResponse, evidenceRequest/evidenceResponse, batchRequest/batchResult or error as an entry point. Every structured object is closed except deliberately open JSON data/attribute/binding maps. This is a specification, not a new executable parser/evaluator or deployed schema URL. Implementers generate/check DTOs against the pinned artifact, without runtime network fetching.

[fixtures.json](fixtures.json) identifies complete valid/invalid structural examples. [semantic-vectors.json](semantic-vectors.json) contains declarative evaluator/validator cases; they specify expected behavior but are not claimed as passing runtime tests. [policy.canonical.yaml](policy.canonical.yaml) gives exact canonical text corresponding to policy.json. Canonical style: block maps/sequences, two-space map indent and indentless sequence entries, sorted map keys, LF terminators, final newline; quote ambiguous scalar values using YAML double quotes and escape control characters. No comments/anchors/tags; operation leaves use C1 order, semantic arrays retain order except defined sets. A serializer must match these bytes and idempotence fixtures; the style is not permission to coerce YAML scalars.

Semantic validators MUST additionally enforce:

1. UTF-8 **byte** bounds and numeric exact/finite range, recursion depth/node counts, ID regex, unique qualified rule IDs, existing rule-set references, strict duplicate keys/tags/aliases. JSON Schema maxLength counts characters, so alone is insufficient.
2. Structural path normalization, alternating collection/key segments, target mount identity, percent decode once, field grammar, no duplicate/colliding requested field targets. Resource path/rowId/table/columns must agree with normalized parsed operations. A caller cannot name a trusted owner/realm by a path alias.
3. DTQL query action requires query except plan-only static gate assessment; non-query forbids query. insert/set mutation is data, update mutation is changes, delete mutation is empty except revision. inspect requires a concrete key/candidate, not a query scan. plan may omit mutation and return residual post-image/field obligations; insert inspect supplies candidate data, not stored evidence. Query inspection uses sample, not a pretend exact point query.
4. Only sample mode has sample metadata/request selection. Exactly one table template, supported get/exists/update/delete, no concrete rowId; update requires changes. Native classes only plan and no query/mutation payload; stored procedure requires callable, others forbid it. Server-derived class must agree with supplied class. Invocation names are resolved canonically, never assumed from caller claims.
5. Every request operation ID unique. Non-sample results map exactly once to each request; sample per-row IDs map to its template and keys. Every blocker/layer/restriction reference resolves to a result operation or sample.templateOperationId (selection domain) in the post-redaction result; allOf=restrictionIds by set. Selection-level facts never increment evaluatedCount. Sample evaluatedCount equals distinct evaluated operation results, ≤requestedLimit; order ends in canonical key. Reducers and allowed equivalence in 15 apply across arrays, not just individual JSON fields.
6. Layer IDs/source ownership anchored in registry; no client-provided policy authority. Private references/revisions/cardinality removed for non-admins; row facts separately authorized. Unknown **input** enum rejects; clients may display a generic error for unknown future returned codes. Consumers must not use a strict old decoder to accidentally turn a rejected future result into success.
7. Evidence requiredFields and response fields match exactly once, no withheld-as-absent. Whole revision and image same snapshot; authorized existence only. A structural schema cannot prove evidence truth.
8. Format/document pair matches: dtql-policy-json requires object, dtql-policy-yaml requires strict text. Owner normalizes missing visibility on PUT using stored value before validation/comparison; create/import defaults public. Canonical output always explicit visibility. capabilities are hints recomputed by owner, never write authority.
9. Class gates and masks follow C7; absence leaves existing route semantics unchanged, present empty allow denies all; duplicate class/namespace entries reject; one scoped stage chain determines each mask. They do not replace policy action/resource checks or authorize unimplemented effects.

HTTP policy create/replace bodies use policyWrite; success uses policyEnvelope with strong ETag. Policy list uses policyPage and bounded opaque cursor; default/max page size 100 and filtering before pagination. Layer discovery uses layersResponse. Unsupported/nonserializable custom policies use policyMetadata descriptors with serializable=false/editable=false, not a fake editable policyEnvelope. No untrusted descriptor reference is a fetch URL.

Schema metadata read uses the host's existing schema response, filtered under schemaRead capability; it is not a new DTQL DDL transport. Existing execution endpoints normalize into C2 operations; their success data payloads remain host-owned, with C2 decision attachment where supported and typed C2 errors on denial. Existence/redaction overrides are in 15.

A3 extensions: collectionMask and fieldMask contain ordered stages. Merge adjacent same-action stages, normalize repeated stars, sort/deduplicate patterns inside each merged stage, and preserve action-change order. nameMask supports anchored stars at any position within one segment; fieldPattern composes such segments with dots and preserves parent-prefix behavior. Legacy fields grammar remains unchanged. Leading/trailing whitespace rejects for new masks, while legacy fields behavior remains separate. field_mask restriction requires representation mask and mask object, or reference with omissionReason. Parent evidence under possible descendant exclusions is unsupported even if the child is absent; ordinary recursive projection is not complete evidence.

Revision domains, mode-specific coordinator lifecycle, selection-level diagnostic IDs, and exact host-owned batch mapping are normative in 15/08. Query text strict decoding uses depth16/node4096/body1MiB limits; policy predicates retain their separate node limits. Mask and native execution policy representation never implies native effects capability.

A3 [scoped stage semantics](../19-scoped-mask-stages.md) govern membership, canonicalization and operational bounds. scoped-mask-vectors.json is a declarative semantic corpus, not a shipped evaluator. A first exclude, empty stages, mixed action keys or the obsolete flat mask form rejects. Adjacent same-action stages are valid and canonically merged as one OR group before applying a type change.

18: // segments, each a literal, a lone "*" (any one segment) or a glob with one
19: // "*" at the start or end ("public_*", "*_id"); a trailing ".*" matches the
20: // whole subtree below the preceding path.
21: type fieldPattern struct {
22: 	source   string
23: 	segments []string
24: 	subtree  bool
25: }

27: // fieldSet is a rule's allow-list. A nil *fieldSet means every field.
28: type fieldSet struct {
29: 	patterns []fieldPattern

33: func parseFieldPatterns(sources []string) (*fieldSet, error) {
34: 	if len(sources) == 0 {
35: 		return nil, fmt.Errorf("access: a fields list must name at least one pattern")
36: 	}
37: 	set := &fieldSet{}
38: 	for _, source := range sources {
39: 		text := strings.TrimSpace(source)
40: 		if text == "" {
41: 			return nil, fmt.Errorf("access: fields contains an empty pattern")
42: 		}
43: 		pattern := fieldPattern{source: text}
44: 		if strings.HasSuffix(text, ".*") {
45: 			pattern.subtree = true
46: 			text = strings.TrimSuffix(text, ".*")
47: 		}
48: 		for _, segment := range strings.Split(text, ".") {
49: 			if segment == "" {
50: 				return nil, fmt.Errorf("access: fields pattern %q has an empty segment", source)
51: 			}
52: 			if stars := strings.Count(segment, "*"); stars > 1 || (stars == 1 && segment != "*" && !strings.HasPrefix(segment, "*") && !strings.HasSuffix(segment, "*")) {
53: 				return nil, fmt.Errorf("access: fields pattern %q: a segment may be *, a prefix* or a *suffix", source)
54: 			}
55: 			pattern.segments = append(pattern.segments, segment)
56: 		}
57: 		set.patterns = append(set.patterns, pattern)
58: 		set.sources = append(set.sources, pattern.source)
59: 	}
60: 	return set, nil
61: }

63: func segmentMatches(pattern, segment string) bool {
64: 	switch {
65: 	case pattern == "*":
66: 		return true
67: 	case strings.HasPrefix(pattern, "*"):
68: 		return strings.HasSuffix(segment, pattern[1:])
69: 	case strings.HasSuffix(pattern, "*"):
70: 		return strings.HasPrefix(segment, pattern[:len(pattern)-1])
71: 	default:
72: 		return pattern == segment
73: 	}
74: }

76: // allows reports whether a dotted field path is readable or writable under
77: // the set: a pattern matches the path exactly, matches a prefix of it (an
78: // allowed parent covers its children), or is a subtree pattern over a prefix.
79: func (s *fieldSet) allows(path string) bool {
80: 	if s == nil {
81: 		return true
82: 	}
83: 	segments := strings.Split(path, ".")
84: 	for _, pattern := range s.patterns {
85: 		if len(pattern.segments) > len(segments) {
86: 			continue
87: 		}
88: 		matched := true
89: 		for i, want := range pattern.segments {
90: 			if !segmentMatches(want, segments[i]) {
91: 				matched = false
92: 				break
93: 			}
94: 		}
95: 		if matched {
96: 			return true
97: 		}
98: 	}
99: 	return false
100: }

102: // enumerable reports the top-level field names the set can be projected to
103: // when no pattern uses a wildcard in its first segment; otherwise ok is false
104: // and callers must fall back to redaction.
105: func (s *fieldSet) enumerable() (names []string, ok bool) {
106: 	if s == nil {
107: 		return nil, false
108: 	}
109: 	seen := map[string]struct{}{}
110: 	for _, pattern := range s.patterns {
111: 		first := pattern.segments[0]
112: 		if strings.Contains(first, "*") {
113: 			return nil, false
114: 		}
115: 		seen[first] = struct{}{}
116: 	}
117: 	names = make([]string, 0, len(seen))
118: 	for name := range seen {
119: 		names = append(names, name)
120: 	}
121: 	sort.Strings(names)
122: 	return names, true
123: }
