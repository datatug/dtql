# A2-S1 supplemental review (Opus, independent)

**Scope:** only the appended A2-S1 collection/column mask delta and its integration into C1/C2/C7, WP1–WP8 and T21. Main A2 review sealed separately; nothing below re-raises main-packet issues.

## Verdict

**Ready with changes.** The reuse decision (extend `access/fields.go`'s parsed `fieldPattern`/`fieldSet` rather than add an evaluator) is correct and the tightening of C7 mask grammar before freeze is an improvement. However, adding *exclusions* inverts a safety invariant that the existing matcher depends on, and the delta asserts the required behaviour in prose without specifying the mechanism. OS-01 and OS-02 should be resolved in the documents before C1/C2/C7 freeze; the rest are pre-implementation clarifications.

## Human decisions (choices, not bugs)

1. **New-column default** (OS-05): allow-list-denies-new vs mask-allows-new. Both are legitimate; the user must choose which the UI produces by default.
2. **Exclusion-mask literal disclosure** (OS-03): whether public policy text may name hidden columns to ordinary callers, given C6 filtered schema. This is a deliberate trade-off between the approved public-by-default direction and column-name confidentiality.
3. **Nested-collection behaviour** (OS-04): fail-closed-unsupported vs deferring `collectionMask` until nested paths are resolvable.

## Reuse assessment — worth preserving

- Extending the audited `fieldPattern`/`fieldSet` with exclusions and reusing `segmentMatches` (`fields.go:63-74`) instead of a schema-snapshot expansion or a second evaluator.
- Keeping `fields` and `fieldMask` mutually exclusive with no silent reserialization; legacy documents keep exact meaning.
- Treating `collectionMask` as a conjunctive gate rather than a path selector with invented specificity — it does not disturb `matchingRules` precedence (`policy.go:353-375`).

## Limits of this review

Assessed only the supplement text plus the `fields.go:1-241` excerpt at the stated SHA. `redactMap` is truncated at line 240, so its array handling and post-projection ordering are inferred, not verified; the query projection call sites of `enumerable()` were not in evidence, so OS-01(c) is an inference from the function contract ("callers must fall back to redaction"), not an observed bypass. No tests were run and no repository was inspected beyond the provided excerpts.
