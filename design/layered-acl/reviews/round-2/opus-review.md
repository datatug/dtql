# Independent Opus review — A2 frozen implementation-plan packet

Executed model: as dispatched (Claude Opus via Claude Agent SDK). No other current-round review was read. No files modified. No tests run; the only runtime evidence I rely on is what the packet itself reports (`01` DALgo `./access ./dtql ./condeval` pass; `contracts/validation.json` structural fixture results). Source claims below cite either a packet section or the excerpts in `reviews/source-evidence.md`.

## 1. Verdict

**Ready with changes.** The architecture is sound, unusually honest about its limits, and demonstrably built on the existing DALgo semantics rather than a new engine. The A2 additions (evidence session, generation publication, sample identity/reducer, C7 gates) are mostly executable as written. However, three items should be fixed **before contract freeze** because they are either an enforcement hole or an unresolvable ambiguity a downstream agent would have to invent an answer for: the missing InGitDB-side capability/grant store (O2-01), the dual field encoding and dot ambiguity (O2-02), and unspecified load-time handling of policy constructs the protected profile refuses (O2-03). A further set of medium items should be resolved in the same document pass; none require architectural invention.

## 3. Missing human decisions and disputed trade-offs (choices, not bugs)

- **Public-by-default visibility (D10).** Correctly implemented as *authenticated* discovery, and the private/admin path is coherent. Fixing O2-04 is the only integrity issue; the default itself is a user choice.
- **Sampling (D08/R17).** Bounded top-N is genuinely useful for Explain and the "never authorizes the whole set" framing (`allowed` forced false, `exhaustive` const false) is the right shape. Cost: it is the only read-producing diagnostic and adds the ID/reducer machinery in O2-05/O2-06. Keeping it is defensible; a human should confirm the added surface is worth it for MVP.
- **`allOf` retention** (O2-15) — simplification vs future alternatives.
- **`now` in v1** (O2-14) — define it or defer it.
- **C7 in MVP.** Representing and evaluating masks while refusing all native/procedure execution is honest and fail-closed (`semantic-vectors: mask-pass-unsupported` → `ACL_ENFORCEMENT_UNSUPPORTED; no invocation`). The residual cost is the authoring hazard in O2-10; the human should accept that a route gate is only as broad as the policy carrying it.
- **Remote conditional write requires readable evidence (D13).** Correctly fails closed; the consequence (no write-only conditional remote path, no remote upsert — O2-08) should be an explicit, acknowledged MVP limitation rather than discovered in WP6.

## 4. Reuse and scope assessment

Reuse is the strongest part of this packet. It evolves `access` rather than adding a second evaluator, and the descriptions of existing behaviour that I could check against the excerpts are accurate: precedence sorting (`policy.go:353` depth→literals→restrictive→name), the write walk (`write.go:119` first matching `Where`, then `checkFields`, then `check`), `check` defaulting to `where` (`write.go:172`), residual disjunction for reads (`policy.go:282`), first-failure return in `context.go:167` correctly identified as the thing WP3 must change, and `explain.go:103`'s `" via "` string-splitting correctly identified as the thing to delete. The fixture in `11` is coherent against those semantics — I traced T01 ([101,105]), T03's "status change may succeed" branch and T07's three blockers, and they hold under the real DALgo write algorithm because the field policies are deliberately unconditional and separate.

Scope is disciplined: no InGitDB server, no SQL authorization parser, no new auth protocol, no long-running transactions, explicit "no MVP implementation authorized". `14` stays advisory. I found no scope creep to remove.

**Worth preserving explicitly:**
1. **The separate row-policy / unconditional-field-policy fixture design** — it is what makes "multiple independent blockers without probing" real rather than aspirational, and it exploits DALgo intersection instead of inventing conditional field denies.
2. **`enforced=false` in every dry run, `allowed=true` only for complete `allow`, `exhaustive` const false** — three small schema constants that structurally prevent a dry-run result from being mistaken for authority.
3. **The generation + committed-HEAD publication ordering with per-phase kill tests (V05)** — the most valuable A2 addition; with O2-09's gaps closed it is implementable as written.

## 5. Limits of this review

I reviewed only the frozen packet plus the excerpts in `reviews/source-evidence.md`. I did not open any repository, so claims about DALgo/OVDB/InGitDB behaviour are inferences from those excerpts and from `01`'s audit narrative; anything outside the quoted line ranges (for example `access/fields.go` pattern matching, which is central to O2-02, and OVDB's existing batch handler shape, central to O2-11) I could not verify and have flagged as such rather than asserted. I ran no tests and generated no telemetry; `contracts/validation.json`'s structural results and `01`'s Go test pass are taken at face value as reported by the packet. Semantic vectors in `contracts/semantic-vectors.json` are, as the packet states, specifications only — I checked them for internal consistency with `15`'s reducers (they agree) but not for executability. Severity for O2-01, O2-02 and O2-03 assumes the referenced mechanisms are genuinely absent rather than present-but-undocumented; if an owner store or a segment-based field matcher already exists in the repositories, those drop to medium documentation findings.
